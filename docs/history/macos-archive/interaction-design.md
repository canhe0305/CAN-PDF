# CANS 文档工作台：界面方向与第一版实现

目标是让正在阅读的 PDF 占据视觉中心，文档操作随着任务出现。设计依据是用户提供的“next-gen 文档工作台”构想。它是交互方向，不代表 OCR、遮盖或文字批注等尚未实现的能力已经可用。

## 信息架构

| 层级 | 内容 | 出现时机 |
| --- | --- | --- |
| 文档层 | PDF 页面、文字层、表单字段、签名和新建对象 | 打开文件后始终占据主要空间 |
| 全局层 | 文件名、打开、翻译、保存、快速操作 | 文件标签与无容器的右上角图标，画布贯穿窗口 |
| 工作层 | 阅读、填写、绘制、签名、搜索、页面导航、缩放 | 顶部图标行、底部查找和页码条 |
| 情境层 | 缩略图、搜索结果、文档信息、所选对象属性 | 操作触发后临时覆盖，不压缩页面 |
| 集中任务 | 签名库、翻译校对、保存确认、快速操作 | 独立浮层，完成或取消后返回文档 |

快捷入口 `Ctrl+K` 只列出已实现的操作，可以输入数字跳转页面；`Ctrl+F` 打开文档搜索。OCR、永久遮盖和文字高亮批注尚未实现，因此没有放入可点击的命令。

## 视觉系统

- 冷纸灰 `#e8eae6` 用作页面外的画布，近白 `#fbfbf8` 用于纸张周围的控件面。主文字 `#252d29`，次文字 `#748079`，有限的深灰绿强调 `#496458`。
- 采用系统 UI 字体与系统中文字体，尽量贴近原生窗口；PDF 自己的字体和版式不受界面字体改动影响。
- 文档页使用单一明显的纸张阴影。浮层用细边框、柔和阴影和少量模糊提示层级，减少永久边框和分栏。
- 不使用贯穿窗口的页首或页尾条；文件名成为轻量标签，常用操作融入背景，缩略图直接贴在画布左侧，底部查找和页码合为窄条。宽窗口默认显示页面列表和文档信息，小窗口自动收起。
- 起始页用一张抽象纸张表达产品，而文档打开后装饰退出，让真实 PDF 成为主角。
- 填写文字时先在右侧选择思源黑体或思源宋体、字号与颜色，再点页面直接输入；点已有文字可在原位修改。两款中文字体随应用提供并嵌入导出的 PDF。原 PDF 中的现有文字仍由阅读层呈现，不会被此工具改写。

## 组件与状态

`App` 管理文档会话、编辑历史和各层显示；`PdfPage` 继续负责 PDF 渲染和表单；`CommandPalette` 负责筛选操作与页码跳转；`SignatureDialog` 管理本机签名；`TranslationDialog` 管理用户 API 配置、发送确认与译文校对。页面列表、搜索框、信息浮层和属性浮层目前由 `App` 组合，后续扩展时可按交互边界拆成独立组件。

## 下一步设计验证

当前“保持排版”的 AI 翻译仍适合白底横排文字，复杂表格和彩底需要进一步设计与排版能力。对象属性已成为情境浮层，但文字选区动作、签名旋转与透明度、批注和 OCR 尚未实现。真实长文档、多窗口尺寸和键盘无障碍还需要专门验收。
