# 核心流程整理：预览、字体与桌面保存

## 已完成

- `pdf/preview-document.ts` 统一主视图与原文编辑框的“修改原文 → 应用批注 → 加载 PDF”流程。取消或失败时释放加载任务；成功后所有权交给调用方，不会因开始下一次预览而提前销毁仍在显示的页面。
- `document/useDocumentPreview.ts` 从 App 中接管 250 毫秒防抖、等待状态、预览替换和卸载清理。已加载但尚未渲染的文档也纳入所有权记录，过期结果不会替换当前文档。失败回调携带原请求的源文档及修订，避免影响后来打开的文档或后来产生的编辑。
- `pdf/fonts.ts` 统一字体需求判断，原文引擎产生回退文字后才决定加载哪些字体。没有新增文字/字段时不读取中文字体；纯宋体或纯系统字体文本不再额外嵌入黑体。原字体缺字的回退行为保留。
- `pdf/write-request.ts` 为写入 Worker 的接收端和发送端统一请求类型，区分检查、预览和保存请求。
- `pdf/binary-request.ts` 与 Rust `binary.rs` 统一 PdfCraft 和普通保存的封装。普通保存改传 PDF 二进制，移除了前端 `Array.from(output)` 及对应 JSON 数字数组。
- `document/native-save.ts` 收拢桌面保存协议。Rust 文件选择/拖放后的读取、保存前的解析与页数校验、文件写入与指纹处理移入 `spawn_blocking`；文件选择对话框仍保持异步。
- 保存继续保留会话令牌、原始编辑源、目标指纹检查、签名保护和临时文件替换；导出副本不改变当前会话目标。
- 更新架构说明和 README 的当前版本入口。App 从本轮开始的 2,110 行降至 2,054 行；重点是明确职责和资源所有权，而非单纯减少行数。
- 操作验证发现旧保存提示条覆盖撤销工具按钮；将反馈提示统一移至工具栏下方，避免保存后出现“按钮点不动”的假象。

## 尚未声称完成的部分

本轮没有通过 Windows 实际保存对话框做完整端到端验收；桌面保存路径已完成编译、前端调用封装测试及 Rust 文件操作测试，浏览器下载不能代替这项验收。

打开和草稿恢复的响应仍使用原有 JSON 数据接口；Worker 仍为短生命周期，整份 PDF 重新生成仍有成本。App 的文件会话、搜索、界面拆分，以及样式归并、测试依赖显式声明与长期性能基准仍可继续推进。

本轮确认消除了冗余字体请求与保存数组转换，没有测量并宣称整体帧率或输入延迟提高了某个百分比。原文编辑的字体视觉一致性、复杂文档段落重排也不是这次重构新增的能力。
