# 编辑与恢复改进：第一批

本轮落实项目检查与 Stirling-PDF 评估中的保存、恢复、字体显示三项。未加入新的运行依赖，未引入 Stirling Java 服务端。裁剪、版本比较、段落换行与 OCR 增强仍属于后续工作。

## 实际行为

- 新增文字输入框支持 Ctrl/Cmd+S 和 Shift 另存为。中文候选字未确认时不触发保存；确认后的输入立即进入修订。保存显式使用输入框的最新内容，避免等待 React 状态更新而保存旧值。
- 首页提供“恢复为副本”。源文件丢失或指纹变化时，可使用草稿保存的不可变源字节与完整修订恢复。恢复副本保持未保存状态，首次保存强制选择全新目标；Rust 后端再次检查，临时文件提交使用不覆盖写入。取消/失败保留草稿，成功后才清理。
- 原文编辑尝试从 PDFium 提取可供浏览器使用的内嵌字体，后台读取并复制字节，在当前编辑器注册 FontFace。退出、取消、加载失败均回收资源。单字体上限 64 MiB，覆盖超过上游 8 MiB 阈值的完整中文字体。
- 对横向文字，用原始字符位置校准起点与均匀字距。输入期间保持真实页面背景；非均匀 TJ/特殊字距和无法加载的字体显示回退提示。

## 仍然存在的边界

没有承诺任意 PDF 输入外观完全无跳动。Base14/raw CFF、子集缺字、特殊字符映射和不均匀字距仍可能使用替代显示；中文整段重排、行首行尾禁则尚未实现。字体读取会增加首次进入编辑的准备工作，尚无长文档性能验收。

中文输出仍可能完整嵌入字体，重复包含现有中文字体的文件可能增大；本轮没有实现字体子集化或全局去重。浏览器功能测试不等于 WebView2/系统文件对话框完整验收，未进行断电、磁盘真实耗尽或并发外部程序压力测试。

macOS 仅同步源码；没有在 Mac 编译或验收，原生字体枚举和 WebKit 行为仍待适配。Vite 的大分块提示仍存在，未通过提高告警阈值掩盖。
