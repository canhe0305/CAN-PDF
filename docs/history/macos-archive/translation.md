# AI API 翻译 — 试验功能

本需求来自用户在白皮书之后明确提出的变更：翻译走 AI API，用户自己填写 URL、模型和 API Key，并提示翻译需要 API。原始白皮书不修改；本变更仅为主动使用翻译时增加可选联网行为。普通阅读、填写和签名继续本地处理。

## 使用

1. 打开普通、未签署、无表单的 PDF，点击工具栏「翻译」。
2. 填写基础 API URL（包含服务商要求的 `/v1` 等前缀）或完整 `/chat/completions` 地址；模型 ID 和 API Key 由服务商提供。
3. 可记住 URL 与模型；API Key 只在当前翻译窗口内保留，关闭后重新填写。修改 URL 会清空当前密钥。当前没有持久保存密钥功能。
4. 「测试连接」只向指定 API 发送固定 `Hello.` 测试块；服务商可能计费，不发送文档文字。
5. 选择简体中文、繁体中文或英文，以及当前页/全文，点击「读取页面文字」。这一步在本机读取，不联网。
6. 校对将要发送的文字块，可排除页眉、公式或敏感片段；勾选显示服务域名、块数、字符数的发送提示，再开始翻译。
7. 原文与译文逐块对照，可手改译文；完成后确认排版限制，生成实际 PDF 预览，再导出译文副本。

第一版接口采用 OpenAI 兼容 Chat Completions 请求，但不要求使用 OpenAI 服务。只兼容该协议的服务可直接接入；不声称自动兼容原生 Anthropic、Gemini、Responses 或任意私有协议。接口依据：[Chat Completions 官方参考](https://developers.openai.com/api/reference/resources/chat)。

## 网络与数据边界

- 保存配置、读取 PDF 和生成排版预览不调用翻译 API。
- 请求包括目标语言、指令、文字块 ID 与所选文字，不包含 PDF 原文件、图片、签名资源、页面坐标或本机路径。文字本身可能含敏感资料，因此必须确认发送范围。
- API Key 只放 Authorization 请求头，不进入 URL、请求正文、本机持久配置或恢复草稿。不记录请求正文或密钥。
- 远程服务要求 HTTPS；回环地址允许 HTTP，便于连接本机模型。拒绝 URL 中的凭据、查询参数和锚点，不跟随重定向。
- 桌面通过 Rust HTTP 客户端请求；浏览器预览直接请求，服务商必须允许浏览器跨域。不会为了绕过跨域而把文档发送到第三方代理。
- 每批最多 40 块、5000 个源字符；逐批发送并显示进度。90 秒网络超时、2 MB 响应上限。不自动重试收费请求。取消停止后续请求并尽力中止当前连接，服务商仍可能对已接收请求计费。
- 严格校验响应 ID、数量和完成状态；不接受缺块、重号、额外块或截断的回复。模型输出当作普通文字处理，不当 HTML、代码或应用指令执行。

## 排版范围与局限

当前是**原位文字覆盖试验版**，并非成熟的任意 PDF 版式重建。

- 保留原页面、页数、图片和页面旋转/CropBox，按文字行或同一基线上的相邻片段提取原位区域。模型只翻译文字，不决定坐标。
- 在原文字矩形覆盖白色底，再写入译文，适用于白底横排文字。字体大小以原字号为上限，最低通常为 7 pt；放不下直接阻止导出，并指出页码。不会裁掉译文。
- 原文底层文字仍在 PDF 内，因此搜索/复制可能同时包含原文和译文；这不是脱敏、删除原文或安全遮盖功能。
- 原字体的粗体、斜体、颜色不完整保留。翻译按片段进行，跨行语义、双栏阅读顺序、复杂表格和段落重排尚未解决。不能承诺完整保留论文排版。
- 竖排、斜排和明确特殊字体片段跳过，扫描页需要 OCR。字体规则不能可靠识别所有公式，用户必须检查并排除不宜覆盖的块。彩色/图片背景可能被白底破坏。
- 签名、加密、表单、已有非空批注或结构标签等文件不支持此导出。读取文字时先在本机预检，不通过就不进入文档翻译；导出前再次检查。
- 读取快照、预检和排版任务均支持取消，取消时终止相应后台计算。
- 单独导出副本。原生保存命令拒绝使用当前源路径作为导出目标，不把译文副本重新设为原会话源文件。
- 中文使用完整 Noto CJK 字体嵌入。目前 fontkit 的 CFF 子集出现可复现的中文字形损坏，完整嵌入修复了检查样本，但使典型输出增加约 13 MB。复杂字形与其他阅读器仍需扩大验收。

## 验证与下一步

自动测试覆盖地址与密钥边界、请求结构、缺块/截断拒绝、取消、收费错误不重试、排版溢出、坐标/源数据保持、中文写入与实际字形渲染。`scripts/mock-translation-api.mjs` 仅用于本机合成样本检查，生产应用不会自动启动它。

真实服务商、真实 API Key、翻译语义质量未测试；没有上传用户文件到外部服务。Windows 原生代码已通过编译，真实 API 与桌面完整交互仍待验收。下一阶段优先做段落与双栏识别、背景保护、可靠的字体子集方案，以及真实文档/阅读器对照。
