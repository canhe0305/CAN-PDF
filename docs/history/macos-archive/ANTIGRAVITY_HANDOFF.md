## 阶段 1：先把这批异步修改验收完整（最高优先级）

### 1.1 补组合层测试

现有新增测试主要针对加载器、目录读取和互斥操作，不能代替 hooks 与原生事件组合的验证。为实际风险补最少的组合测试；必要时可添加明确声明的测试依赖，不要搭建第二套应用框架。

必须覆盖：

1. 正在读取 A 时再次拖入 B，不启动重叠文件读取，不留下无人管理的原生令牌；操作结束后 C 可以正常打开。
2. A 已显示且目录还没返回时打开 B，A 的迟到目录、能力检查、错误提示不得覆盖 B。
3. 旧草稿清理或 `release_document` 失败，新文档仍能完成能力检查；给出准确提示，不能长期停在只读或“正在打开”。
4. 在文件选择、读取字节、PDF 解析、页面元数据、原文预览等不同等待阶段卸载，后台资源正确释放，迟到结果不能重新占用会话。
5. 未保存文档的打开、拖入和关闭：取消保留修改；保存失败保留修改；取消文件选择保留旧草稿。确认框不能出现两次，也不能残留一个永远不结束的 Promise。
6. 检查保存和草稿恢复期间卸载、并发操作的边界。这两条流程尚未做完整统一的取消治理；发现问题时用实际复现和测试修复，不要仅凭推测宣称已经存在数据丢失。
7. 密码文档显示明确限制并退出等待；失败后能正常打开另一个文档。

## 阶段 2：用测量找剩余卡顿与内存负担

先建立可重复的基线，再改热点。不要凭文件行数、主观感觉或项目目录体积判断性能。

样本至少包括 100 页文字文档、50 页含图文档、含多笔画签名/多个文字框的编辑会话；先确认样本真实页数和对象数量。记录机器、版本、窗口大小和缩放比例，区分冷启动与热启动。

| 操作                     | 需要测什么                                                 |
| ------------------------ | ---------------------------------------------------------- |
| 打开、显示首屏、允许编辑 | 分阶段耗时；目录读取不得计作首屏前置依赖                   |
| 连续滚动、拖动文字/签名  | 主线程长任务、帧间隔分布、重渲染范围                       |
| 连续输入中文/英文        | 输入到画面响应、预览刷新次数、每次键入是否重复处理整份 PDF |
| 缩放后停止               | 高清重绘次数、画布数量和大小                               |
| 连续切换 20 次文档       | Worker、PDF 实例、Canvas、监听器、字体和内存的保留趋势     |
| 大量编辑与撤销           | 历史快照和脏状态判断的成本                                 |

重点候选位置：

- `revisionKey` 仍整体 `JSON.stringify` 修订；大图片或笔画可能放大每次更新的成本。先量出它是否真是热点。优化时必须保持“撤销回已保存状态后不脏”、空编辑与实际保存一致，不能用容易碰撞的散列直接判定文件已保存。
- 首屏展示仍等待全部页面元数据。若要渐进加载，保持稳定 `pageId`、旋转/CropBox、恢复稿和页面操作语义。
- `PdfPage` / `Thumbnail` / `InlineOriginalEditor` 的代理、画布及异步失败回调：检查旧请求是否污染新状态，以及不可见页面是否持有过多资源。
- 原生打开/恢复仍使用 JSON 数字数组；若测出明显峰值，再做二进制接口，并同步修改调用方、验证边界与恢复兼容性。

阶段 2 完成条件：提交前后同机同样本数据、实际修复的热点及回归结果。不要求靠删除功能换性能，也不允许把“拆了文件”写成“明显提速”。

## 后续独立功能：中文字体与段落重排

这不是一次代码清理可以顺带承诺完成的工作。用户确实重视接近 Acrobat 的原位编辑，应保留为独立阶段：

- 当前按 PDF 文字对象编辑，尚非完整段落编辑；扫描图片、曲线字、复杂嵌套对象等有真实限制。
- 先设计行/段落识别、基线、字距、换行边界、相邻内容避让以及回退策略，再选择一个可验收的小范围实现。
- CJK 字体当前完整嵌入，是已有 CFF 子集字形问题的取舍。任何子集优化必须通过真实中文字形渲染、搜索、重新编辑与保存往返测试；文件变小不代表文字正确。
- 不得把白底覆盖、整页栅格化或普通 OCR 层包装成“已实现任意原文编辑”。
