## 后续重点，按优先级排序

### 1. 收拢原文预览与保存流程，并测量重复工作

位置：`src/App.tsx` 的原文预览 effect、`src/features/original-text/InlineOriginalEditor.tsx` 的背景生成 effect、`src/features/original-text/service.ts`、`src/pdf/write.worker.ts`。

文档预览和当前编辑框背景分别组织原文写入、批注处理、PDF.js 加载及取消清理。两条流程用途不同，但共享的处理步骤散落在组件中，修改生命周期时容易只修到一处。

当前每次原文预览都会创建新的写入 Worker；其中又无条件读取整份 Noto Sans CJK 字体，即使 `writer.ts` 最终判断不需要嵌入字体。这是明确存在的额外处理，不等于已经证明它是卡顿的主要原因。

建议先把字体需求判断集中到写入层，实现按需读取，再抽出有明确资源所有权的预览服务。缓存和复用 Worker 应后置，并验证取消、切换文档、撤销及保存不会使用旧结果。用同一批中英文 PDF 比较输入到预览完成的耗时及内存，不能仅凭构建通过声称更流畅。

### 2. 统一普通文件保存的传输方式

位置：`src/App.tsx` 保存中的 `Array.from(output)`、`src-tauri/src/files.rs` 的 `Opened` / `save_document`；对照 `src/features/pdfcraft/service.ts` 的 `pdfRequest`。

普通打开和保存仍通过 JSON 数字数组传递 PDF，PdfCraft 已使用二进制传输。大 PDF 的数组创建和序列化会带来额外分配，两个接口也形成了重复约定。建议统一二进制传输和响应类型，同时保留会话令牌、目标指纹和安全替换流程。

`files.rs` 的异步打开/保存命令中还直接进行同步文件读取、PDF 解析、哈希与落盘；PdfCraft 已将类似工作放入 `spawn_blocking`。需要统一调度方式，避免阻塞异步执行线程。是否造成用户可见停顿仍需实测。

### 3. 按职责拆分 App 与页面组件

位置：`src/App.tsx` 2,110 行，`src/components/PdfPage.tsx` 712 行。

App 同时负责文件会话、草稿、撤销历史、原文预览、搜索、快捷键、窗口事件和界面。建议先提取文件会话与保存、预览资源生命周期、搜索三个独立模块，再拆界面组件；不要只为了缩短文件，把互相依赖的状态搬到不同文件。

PdfPage 的表单注释仍使用 `any[]`，选项也使用 `any`。应在 PDF.js 返回值边界定义并验证实际支持的 Widget 数据，而不是用强制类型断言掩盖未知字段。

### 4. 合并仍生效的样式覆盖

位置：`src/App.css`。

删除死样式后仍有较大体积；基础布局、“Reading room”、无边框窗口和简化首页的规则分散在不同段落。同一选择器重复出现，其中一些是正常响应式规则，一些则来自设计迭代。

下一轮应按窗口、首页、阅读画布、浮层分组，归并同一组件的最终规则。需要在多个窗口尺寸下对比截图，不能仅凭搜索“重复选择器”就删除。

### 5. 完善检查范围与测试可重复性

- `tsconfig.json` 的类型检查只包含 `src`；测试和脚本由运行器转换，尚无独立完整类型检查。可增加单独配置逐步处理，而不是关闭严格模式。
- 目前没有 ESLint / React hooks 专项静态检查。现有严格类型选项能发现部分无用声明，但不能代替 hooks 依赖审查。
- 多个渲染测试直接导入 `@napi-rs/canvas`，根 `package.json` 未将其声明为直接开发依赖，当前依赖树使其可用。应显式锁定测试直接使用的依赖，减少依赖树变化造成的环境差异。
- 许多测试输出直接写入 `tests/fixtures`，输入样本、生成结果及历史手工验证结果混放。建议分开固定输入、临时输出和留档证据，并约定清理规则；本轮未删除这些文件。
- Rust 自有源码大量使用压缩成一行的声明和函数，影响阅读。当前工具链没有安装 rustfmt/clippy，本轮未执行这两项检查，也未格式化第三方 PdfCraft 源码。

### 6. 建立清晰的源码与交付版本对应关系

当前目录没有 `.git` 元数据，无法通过 Git 对比确认本轮之前的全部改动。建议将源码、配置、必要样本纳入版本控制，排除 `target`、`dist`、依赖目录与临时验证输出。

README 已修正当前操作说明，但 `docs/architecture.md` 等还保留早期状态描述，例如原文编辑引擎未列入架构、历史输入合并仍被写成待优化。应区分当前说明与按日期保留的验证记录，避免用户把旧安装包、历史可执行文件与最新源码混为一谈。
