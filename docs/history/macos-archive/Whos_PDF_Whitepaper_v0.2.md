# Whos PDF 产品与开发白皮书

白皮书版本：0.2  
日期：2026 年 10 月 5 日  
产品名称：Whos PDF  
首个产品版本：0.1  
形态：本地优先的桌面客户端  
目标平台：macOS、Windows；Linux 后续评估  
用途：产品定义、开发范围、架构约束与验收依据

## 1 产品定义

Whos PDF 是一个以阅读、填写与签名为核心的 PDF 桌面客户端。用户打开文档后，可以阅读、填写已有表单、在普通页面添加文字、放置手写签名、调整页面并保存。

产品围绕连续工作过程组织：打开 → 阅读 → 填写 → 签名 → 保存。文档始终占据界面中心，工具只在操作需要时出现。

长期目标是在简洁的桌面交互中提供可靠的 OCR、填写位置检测、证书签署与签名验证。第一版优先交付完整可用的日常处理过程。

本白皮书中的“必须”属于对应版本的验收要求；“后续”属于路线规划。白皮书版本号不等于产品版本号。

## 2 目标用户与核心场景

目标用户包括处理申请、合同、行政材料的个人，以及阅读论文和教学文件的研究者、教师和学生。

首个版本必须完成四种场景：

1. 打开标准表单，填写姓名、地址等内容，勾选选项，放置手写签名并保存。
2. 打开无表单字段的申请材料，在指定位置添加中文或英文文字、日期和签名并保存。
3. 打开多页材料，调整页面顺序、旋转或删除页面，保存为新文件。
4. 打开已有数字签名的文件，显示存在签名的提示并保护原文件；未实现验证时明确显示“尚未验证”。

## 3 产品原则

### 3.1 文档优先

启动页仅提供打开文件和拖入文件的入口。打开后直接进入阅读界面。主界面不采用工具卡片墙、复杂仪表盘或工具数量展示。

### 3.2 本地优先

默认在本机完成阅读、填写、批注、手写签名、页面管理和 OCR。不上传 PDF、识别文本、表单内容、签名图片或私钥。第一版不设置账号系统，不接入云端 AI，不默认开启遥测。

后续版本的证书状态查询和时间戳服务可按需联网，须说明用途。更新检查与语言包下载属于独立网络行为，不能夹带文档数据。

### 3.3 渐进呈现

默认显示文档、紧凑工具栏和可隐藏侧栏。进入批注或填写状态才显示相关工具。选中对象时才显示属性面板。

### 3.4 桌面行为一致

遵循系统快捷键、打开与保存对话框、拖放和窗口行为。所有修改提供可见的未保存状态；关闭前允许保存、放弃修改或取消关闭。

### 3.5 文件完整性优先

界面中的内容必须能够写入标准 PDF。保存失败不得破坏原文件；不支持的文件必须明确说明限制，不能把看起来正确的页面当作保存成功。

## 5 文件打开与兼容边界

打开后先呈现可见页面，再执行轻量结构检查：页数、文字层、表单、批注、加密状态和签名相关结构。检查必须能够取消，不阻塞滚动。

兼容状态分为可编辑、只读和无法打开。判断不确定时采用只读状态，并说明原因。

| 文件情况 | 0.1 行为 |
| --- | --- |
| 普通未加密 PDF | 支持范围内允许编辑 |
| 扫描 PDF | 允许阅读、手动添加文字和手写签名；提示无可搜索文字 |
| 密码保护 PDF | 阅读引擎支持时要求密码；写入引擎不支持时保持只读 |
| 已有数字签名 | 默认只读；可保存原始副本；修改副本必须明确签名影响 |
| XFA 或依赖复杂脚本的表单 | 提示填写限制；不能静默删除相关结构 |
| 损坏或异常结构 | 能显示时提供只读阅读；不能安全保存时禁用写入 |

不执行 PDF 内嵌 JavaScript、启动动作或附件程序。网页链接经用户点击后调用系统浏览器；网络或文件动作不能自动触发。文件密码不写入日志。

## 6 阅读与性能

采用按需渲染和缓存。优先渲染当前及相邻页面；不可一次渲染全部页面。缩略图使用低分辨率，OCR 和保存等任务移出界面主线程。

搜索支持结果计数、上一个和下一个结果、跳转及高亮。扫描文档没有文字层时，不把零搜索结果解释为文档没有该内容。

已有书签与大纲用于导航；编辑书签放到后续版本。连续滚动为默认模式，单页模式可后续加入。

性能验收记录实际机器、文件和耗时；不在未经测试时承诺固定打开速度。至少检查 100 页普通 PDF 和 50 页扫描 PDF 的打开、滚动、内存变化与关闭回收。

## 7 填写与表单

### 7.1 普通页面填写

点击“填写”后，可以在页面放置文字、日期或勾选标记。支持字体大小、颜色、对齐和对象位置调整。默认值应足以完成常见申请，不要求用户先配置属性面板。

中文字体必须嵌入或使用经过验证的可靠写入方案。保存后不能依赖收件人的电脑安装同一种字体。缺字时提示，不能输出空白或乱码。

### 7.2 常见 AcroForm

0.1 支持文本、多行文本、复选框、单选框、下拉框和列表选择。Tab 与 Shift+Tab 按文档字段顺序移动；已有合理顺序时优先保留。

字段值与外观必须同时保存。日期选择器属于应用提供的输入辅助，不承诺执行 PDF 中任意日期脚本。暂不支持复杂计算、验证脚本、动态 XFA 和完整表单创作。

现有签名字段的定位，与放置手写签名、通过证书签署分别处理。第一版不得把填入签名图片描述为完成证书签署。

### 7.3 后续填写位置检测

先读取已有字段，再按页检查文字层质量，必要时运行 OCR，最后结合文字标签、横线、方框和空间关系生成候选区域。

优先检测姓名、日期、签名、首字母签名和复选框。候选结果仅作为界面提示；用户确认后才创建填写对象。支持忽略、纠正和手动创建。对自动推断的字段，系统不能自行填写或保存。

## 8 手写与图片签名

面向日常填写，提供鼠标或触控笔绘制、透明 PNG 导入、多个签名的保存与删除。触控板专用捕捉和相机去背景后续实现。

用户选取签名后在页面放置，可以移动、等比缩放、旋转和删除。签名可保留为矢量笔画或透明图像，不添加不必要的背景。图片导入限制格式和尺寸，异常图片需安全拒绝。

签名资源放在应用私有本机目录，提供删除与清空入口。第一版不保存证书私钥；后续优先使用系统密钥管理。

界面命名为“手写签名”或“图片签名”。此功能不提供密码学身份验证或文件防篡改证明。

## 9 批注与页面管理

高亮对应真实文字选区；没有文字层时不伪装成文字高亮。文本批注、自由绘制和普通页面填写对象在内部使用明确类型。

原有批注应尽量保留。编辑已有批注可分阶段实现，但不能因保存新批注而静默清除原有内容。

页面通过侧栏拖动排序；右键提供旋转、删除等操作。多选操作和拖动排序可撤销。必须用稳定页面标识关联对象，不能只依靠会变化的页码索引。

页面操作若无法正确保留受影响的表单、书签、批注或其他结构，应阻止该操作或将文件保持只读，直到提供可靠实现。复制、插入、提取、裁剪、合并和拆分后续加入。

## 10 保存与恢复

### 10.1 保存

保存到普通 PDF，保留支持范围内的表单与批注结构。新建的应用对象必须写入 PDF 内容或标准批注，不能只留在旁边的项目文件中。

会话内所有新建对象可编辑。跨会话的对象恢复能力必须明确：已写为页面内容的对象不承诺重新识别成可编辑对象；支持的标准批注和表单可重新加载。不得把“会话内可编辑”宣传为“永久可编辑”。

### 10.2 固定外观副本

提供“导出固定外观副本”，将适用的填写内容、批注和手写签名固定到页面。原文件保留。固定外观不能防止其他软件修改，也不等同于数字签名。

### 10.3 安全写入

先在目标目录写入临时文件，完成后检查输出能够解析、页数符合预期、预期字段与对象仍存在，再提交替换。使用平台支持的安全替换方式。提交前再次检查目标是否被外部修改；发生冲突时提示另存为。

保存失败时保留原文件和恢复草稿，展示明确错误。任何失败分支不得清除未保存标识。磁盘不足、权限不足、输出被占用以及写入中断都要覆盖。

已有签名文件不得通过普通重写路径覆盖。修改副本时说明签名可能失效；无法安全处理其结构时拒绝编辑。

### 10.4 恢复草稿

在应用私有目录定期保存未提交修改，记录原文件指纹与版本。恢复前检查源文件变化；不能把旧草稿自动套用到不同文件。成功保存或明确放弃后清理草稿；提供清空恢复数据入口。

## 11 OCR 路线

产品 0.2 提供本地 OCR。按页判断文字层质量，支持文字页与扫描页混合的文件，避免重复识别已有有效文字。

先支持英文与简体中文，再通过真实材料验证繁体中文、日文、韩文及其他语言。语言模型按需安装，并显示语言、下载大小和处理进度。

OCR 任务支持选择页范围、取消和失败重试。完成后文字可以搜索、复制；是否写入 PDF 由保存操作决定。生成文字层应尽量保持原页面外观。

已签署文件可以在本机缓存 OCR 结果用于阅读和搜索，但不得未经明确操作把文字层写入原文件。

评估 Tesseract 等本地引擎。OCRmyPDF 可作为备选流水线，但必须验证依赖、安装包体积、跨平台分发和相关许可证；第一版不要求用户安装 Python、Docker 或 WSL。

## 12 数字签名与验证路线

产品 0.3 增加通过证书签署与验证。先实现一个明确的 PAdES 基线配置，再扩展时间戳、吊销检查与长期验证；不能以笼统“支持 PAdES”代替兼容测试。

技术范围涉及 X.509 证书、CMS、SHA-256 和 PKCS#12 文件。优先评估成熟 PDF 签名实现，例如 pyHanko，再决定本机进程的封装方式。OpenSSL 或 Rust 密码学库本身不能替代 PDF 签名协议、增量写入和验证逻辑。

默认引导用户完成修改后签署。签署后的进一步操作根据签名覆盖范围、DocMDP、FieldMDP 和增量更新规则处理。多方签署及验证资料追加需要独立测试。

验证应分别记录密码学完整性、签名覆盖范围、后续修改、证书链信任、吊销状态和可信时间。界面结论至少包括：验证通过、签署后有修改、证书不受信任、验证失败、无法确定、尚未验证。

自报签署时间不能显示为可信时间戳。证书现在过期，也不能直接代替历史签署有效性判断。离线和缺少资料时显示限制。允许用户查看签署者、证书、算法、时间来源及修改情况。

0.1 不实现证书签署，但预留独立服务接口并保护已有签名文件。

## 13 界面规范

默认结构：顶部紧凑工具栏、可隐藏左侧页面与大纲栏、中央文档、按需出现的右侧属性面板。

工具栏优先提供侧栏、搜索、填写、批注、签名、缩放和保存。打开与其他操作同时存在于菜单和快捷键中。签名菜单未来分别列出手写签名和证书签署。

使用系统字体、中性颜色、细分隔线和小尺寸控件。避免大面积渐变、巨型圆角按钮、工具卡片墙和 AI 对话首页。正文页面占据主要可用空间。

编辑模式只能有一个明确的当前状态：阅读、填写、批注或签名放置。Esc 退出当前放置操作。侧栏与属性面板的显示不能导致对象坐标变化。

所有按钮具备文字提示和键盘焦点。支持基本键盘导航。中文和英文 UI 文案集中管理；不把实现技术展示给普通用户。

窗口标题示例：contract.pdf — Whos。未保存时增加清晰状态标记。

## 15 技术架构

基础候选为 Tauri 2、React、TypeScript 和 Rust。Tauri 负责桌面窗口与系统集成，React 负责界面；PDF.js 负责阅读显示。应用打包为桌面客户端，开发服务器不能代替交付物。

| 层 | 职责 |
| --- | --- |
| 界面 | 工具栏、导航、字段交互、对象操作和错误提示 |
| 文档会话 | 页面标识、字段值、新建对象、修改记录、撤销与重做 |
| 阅读适配器 | 页面渲染、文字提取、坐标转换、搜索和大纲 |
| 写入适配器 | 能力声明、表单与批注写入、页面操作、保存及输出检查 |
| 本机服务 | 文件读写、权限、恢复目录、任务调度和系统集成 |
| 后续服务 | OCR、候选字段检测、数字签名与验证 |

所有对象使用 PDF 页面坐标，统一处理缩放、旋转、CropBox 与设备像素比例。不能直接把屏幕像素作为保存坐标。

pdf-lib 可用于早期未加密文件的实现验证，不作为全部写入能力的保证。签名文件、加密文件和复杂结构根据写入适配器声明限制。后续选择 PDFium、MuPDF、qpdf 或其他库时，逐项验证实际能力、维护状态、平台支持及许可证；不同时引入多个引擎来承担模糊重叠职责。

Tauri 的文件及命令权限应最小化。外部 PDF 不获得调用本机命令的能力。OCR 与其他本机子进程使用结构化参数和明确输入输出，不通过拼接 shell 命令传入用户文件名。

## 16 开发阶段

### M0 核心风险验证

建立桌面工程，先验证真实 PDF 的显示、中文文字、常见字段、手写签名放置、写入和重新打开。覆盖旋转页与不同页面尺寸。记录写入引擎限制及许可证。

输出可运行工程、样本说明、兼容矩阵和技术决策记录。若关键能力不能可靠实现，先调整适配器或缩小范围，再制作完整界面。

### M1 阅读与保存基础

实现打开、渲染、搜索、缩略图、基础会话、另存为、只读文件判断和关闭提示。

### M2 填写与手写签名

实现普通页面填写、常见 AcroForm、中文字体、签名创建与管理、放置及对象操作。完成撤销、重做和固定外观导出。

### M3 批注与页面管理

实现常用批注、页面排序、旋转与删除；验证所有操作组合及保存结果。

### M4 桌面交付

完成恢复草稿、安全写入、系统打开行为、安装包和跨软件兼容检查，形成产品 0.1。

macOS 与 Windows 分别构建和测试。没有对应构建环境时明确标记未验证，不能将浏览器运行成功视为双平台完成。公开发行前完成对应签名与 macOS 公证；测试安装包的状态需明确。

### 后续版本

0.2：OCR、语言管理和候选填写位置检测。  
0.3：证书签署、验证、时间戳与签名权限处理。  
以后：页面插入与提取、合并、拆分、裁剪和其他经过验证的需求。

## 17 验收依据

使用合法取得且不含真实敏感资料的测试样本。至少覆盖：普通文字 PDF、扫描 PDF、混合 PDF、常见 AcroForm、中英文填写、旋转页、不同 CropBox、已有批注、已有数字签名、密码保护文件、XFA 和损坏文件。

必须通过以下检查：

1. 在不同缩放和旋转下放置的文字、签名，保存后位置与尺寸一致。
2. 中文填写保存后在其他阅读器中不乱码、不缺字。
3. 表单的值、勾选状态和可见外观一致。
4. 页面调整后，保留内容及对象关联正确；不支持的组合被明确阻止。
5. 撤销和重做覆盖新建对象、移动、删除、字段修改与页面操作。
6. 保存失败、权限不足、磁盘不足或外部修改冲突时，原文件仍然可用。
7. 保存输出能够重新打开；固定外观副本与保留表单的版本行为符合说明。
8. 已有签名文件默认只读，不显示未经验证的有效结论。
9. 应用异常退出后能够恢复未提交修改，并检查源文件变化。
10. 核心操作断网可用，无隐含远程字体、脚本或文档上传请求。

保存结果至少在 Acrobat Reader 与另一个独立阅读器中检查；macOS 构建还需在 Preview 中检查。记录阅读器版本和观察结果，不预先承诺所有 PDF 兼容。

测试重点放在坐标转换、字段外观、保存失败保护和完整工作流。建立自动化单元与集成测试，并进行实际桌面验收；截图和静态页面不能替代文件输出验证。

## 18 开发交付要求

工程至少包含 README、依赖与许可证记录、支持能力表、已知限制、测试样本生成方式、测试命令以及打包说明。

## 19 产品边界

暂不处理 Word 式文字回流编辑、完整印前检查、云文件管理、电子签约平台和大量格式转换。新增功能需证明能够改善从打开文件到完成保存的过程。

产品质量以成功完成真实材料的比例、保存可靠性和操作成本衡量，不以功能数量衡量。软件界面保持简洁，文件处理过程保持可检查。
