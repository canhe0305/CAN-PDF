# 技术决策

1. 从空目录建立 Tauri 2 + React + TypeScript 工程。白皮书作为产品参考和验收约定，附件中的启动指令不被当作额外授权；执行范围来自用户要求“读白皮书并开始干活”。
2. M0 使用 pdf-lib 作受限写入验证，以 PDF.js 作独立读取与渲染检查。对签名、加密和复杂结构不承诺完整写入兼容。暂不引入第二个写入引擎。
3. Noto Sans CJK SC 随应用分发并嵌入 PDF 子集，不依赖收件人本机字体。测试发现纯签名保存会触发 fontkit 空 CFF 子集异常，已以预置空格修复并加入 PNG 保存回归测试。
4. 页面操作从严格能力声明开始：检测有风险结构时拒绝。首次测试发现空 Annots 数组导致误禁用，已改为判断非空数组；脚本检查递归检查内嵌字典，避免漏掉直接对象。
5. 普通保存保留源文档结构。固定外观导出仅支持可处理范围，遇到已有非表单批注明确失败，不把部分固定称为成功。
6. 原生 Rust 服务负责文件落盘与恢复数据；浏览器预览只允许生成下载，未获知下载完成时保留未保存标识。
7. M0 视觉方案：页面白 #ffffff、工作区灰 #e9ecf0、工具栏灰白 #fcfcfd、文字 #283342、弱文字 #7a8491、操作蓝 #345b85；UI 系统字体，PDF 覆盖文字使用内置 Noto。顶部窄工具栏、左侧页面、居中文档、按需右侧属性。主体左对齐，空态居中；不设置卡片墙、云入口或无效功能按钮。
8. 前端精确版本及 package-lock 已记录；Rust 因网络解析失败尚未形成 Cargo.lock，桌面发行前必须生成并固定依赖。
9. 按 AGENTS.md 调用了 Gemini CLI 做限定模块只读复核，CLI 提示登录后无法继续；已停止该进程。本次不声称完成 Gemini 复核。

官方接口依据：[Tauri 工程](https://v2.tauri.app/start/create-project/)、[PDF.js 示例](https://mozilla.github.io/pdf.js/examples/)、[pdf-lib 表单](https://pdf-lib.js.org/docs/api/classes/pdfform)。具体调用同时核对已安装版本的类型声明。

## 后续变更：用户自带 API 翻译

用户明确要求可选的在线 AI 翻译和自填 URL/模型/Key，详见 `translation.md`。默认本地原则保留，只有连接测试和经确认的文字翻译可以联网。

实际译文 PDF 渲染发现 fontkit 的 CFF 子集损坏部分字形（文本提取仍正常），所以普通填写与翻译改为按需完整字体嵌入。这取代上文第 3 项的子集策略；文件体积增加，不能用“可搜索”代替“显示正确”验收。
