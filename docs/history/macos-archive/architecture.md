# 架构与不变量

React 负责交互，PDF.js 负责阅读，PDFium 负责编辑真实原文对象，pdf-lib 负责新增对象、表单与受限页面写入；PdfCraft 负责标准批注和文档工具，Tauri/Rust 负责本机文件行为。

`document/useDocumentPreview.ts` 管理防抖预览与已加载文档的所有权；`pdf/preview-document.ts` 为主视图和原文输入框统一原文修改、批注、PDF.js 加载及取消处理。`document/native-save.ts` 管理普通保存的桌面接口。`useDocumentSession` 负责加载、保存、历史和草稿，`useDocumentNavigation` 负责打开/关闭确认与原生窗口事件，`useDocumentSearch` 负责延迟搜索与过期查询取消，`useDocumentView` 负责视口定位与缩放。App 组合这些职责并协调工具/编辑状态；侧栏、文档信息、搜索和表单各有组件。PDF.js 表单注释经 `pdf/form-widgets.ts` 校验后才进入表单控件。

## 数据

页面记录 `{ id, sourceIndex, rotation }`；对象绑定稳定 `pageId`，不绑定展示页码。对象坐标为 PDF 用户空间。PDF.js viewport 的正反变换处理缩放、旋转和 CropBox；SVG 用同一变换显示对象，写入时直接使用 PDF 坐标。

历史是不可变修订快照，包含页面、对象、字段值、原文编辑和批注修改；最多保留 100 次历史。保存基准通过修订的序列化值比较，失败和取消都不清除脏状态。原文输入即时更新修订，同一编辑框的一轮输入合并为一次撤销，PDF 预览防抖 250 毫秒；大文档历史内存仍需基准测试。

保存始终从打开时源字节和完整当前修订生成，避免多次保存重复叠加。目标路径及指纹由 Rust 会话令牌记录。恢复稿同时保留原始源字节与当前目标指纹，恢复前拒绝指纹变化的源文件。

## 写入与安全边界

写入适配器每次保存重新检查能力。包含签名、XFA、脚本动作、不支持字段或不能被安全解析的文件采用只读状态。页面操作对表单、非空批注、大纲、命名目标、结构树、页标签采取保守禁用。普通保存保留原结构，不复制成全新空文档。

新增文本可使用本地思源黑体、思源宋体或支持嵌入的系统字体。普通写入 Worker 在原文编辑产生回退文字后，统一按 `pdf/fonts.ts` 的需求判断加载字体：原字体编辑、绘图和签名不读取中文字体包；仅宋体文本不再额外嵌入黑体；字段修改仍加载黑体供表单外观使用。原字体缺字时先移除真实文字对象，再用回退字体写入。实际翻译渲染发现 fontkit CFF 子集会损坏部分中文字形，因此仍完整嵌入所需 CJK 字体。PDF 写入与结构检查在短生命周期 Worker 运行，成功、错误、120 秒超时均终止 Worker。

普通桌面保存和 PdfCraft 操作共用二进制请求封装：4 字节小端元数据长度、UTF-8 JSON 元数据、PDF 字节。普通保存不再把 PDF 展开成 JSON 数字数组。文件选择/拖放后的读取、普通保存的 PDF 解析与落盘使用后台阻塞任务；打开和草稿恢复的响应目前仍使用原有 JSON 数据接口。

原生提交顺序：解析输出 → 检查页数 → 在目标目录创建临时文件 → 写入并同步 → 再查目标指纹/签名 → tempfile 平台替换。其安全性仍需 Windows 故障注入与占用测试；检查与替换间的并发竞争未声称得到绝对消除。

CSP 禁止远程脚本、对象和框架；无任意 shell 命令接口。PDF 内嵌脚本、链接与附件动作没有执行入口。外链交互尚未提供。所有 PDF.js CMap、标准字体、WASM 和 CJK 字体打包在本地。

## 当前技术债

首次打开分批取得页面元数据，尚未做到首屏展示与全量结构检查完全解耦。画布按视口渲染，但长文档页面代理和历史内存仍需基准测试。搜索按文本片段扫描，未建立完整选区索引。原生读取接口限 PDF 扩展名、256 MB；读取响应仍可进一步改用二进制。

恢复草稿在应用私有目录保存不可变原始 PDF 和单独的修订 JSON，暂未加密或压缩；仍支持旧版把源字节写进 JSON 的草稿。签名存于桌面 WebView 私有本机存储。需要补配额、设置内清空入口和崩溃/磁盘不足验收。
